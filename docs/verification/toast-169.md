# 169 现有临时反馈统一出口

用户要求：只迁移原先显示在页面上的临时错误/操作提示，固定屏幕中央；不为原来没有提示的操作新增toast。持续业务状态、真正空结果、任务进度与确认对话框保留。

## 实现

AppToast.swift提供existingFeedbackToast单一出口。每个来源按owner、scope、原事件ID识别，局部来源受可见页面约束，全局session.message可显示在整页播放器之上；onShown只确认并清空原消息，不立即移除已显示toast。窗口内只有一个透明、触摸透传的host，固定窗口中心，沿用App字体、圆角与留白。相同事件重渲染不重发，不同事件的同文提示合并并重新保留3.2秒；离开来源/身份变化移除对应来源。无错误时局部来源不创建UIKit适配器。

## 迁移范围

- App根session.message、登录错误、原FailureView；保留重试/登录操作。
- 媒体读取、播放兼容错误、详情读取/屏蔽失败、作者简介失败、续加载失败；保留原重试、恢复、冷却及任务状态，不改变媒体队列。
- 作者榜/关注原失败：缓存刷新仍仅原文“刷新失败”，不把此前隐藏的raw error变成新反馈。
- 搜索、标签目录/作者选择的既有读取或输入校验错误；输入错误清除时可以提前消失。
- 本机诊断、已存条件、屏蔽作者/标签、标签库错误、空间清理结果；不监听全局下载队列错误。标签库暂停、网络和正常进度仍是业务状态。
- 最近浏览读取/信息读取/播放失败、既有相邻作品定位提示；收藏编辑/批量编辑错误；TimelineLane仅原notice.isError。收藏根错误仅原FailureView分支，非错误notice不新增显示。
- 账号设置删掉重复拷贝session.message的本地卡片，只由根出口显示。

来源迁移worker已给独立审核员逐项原可见文案/条件及保留操作说明。168只有manifest而无完整冻结源码副本，严格逐行等价证明存在边界；不能把git HEAD视作168基线。

## 验证与边界

r1编译失败：CGRect/UIView.convert的.zero存在歧义，已明确CGPoint.zero；原失败log保留。

r2优化模拟器5/5通过（build/toast169-r2.log），source-before/after一致：7f651327c8b4849c11a909323969c3a9ae340af741cc13b80a441530e8ef8182。包括中央位置/触摸透传/失活与无提示动作/长文本/来源移除、收藏失败关闭编辑页后仍显示、作者播放器上方显示、账号切换丢弃晚到错误，以及作者选择器双侧返回。

独立读回截图：短提示贴合内容居中，长提示最多三行；作者播放器上方原收藏失败消息居中。QA截图名称central-light实际使用跟随系统深色，不能据文件名宣称白色QA页覆盖；播放器截图实际显示浅色toast。截图导出在build/toast169-r2-attachments/。

r2后审核发现同文新事件近旧截止时间会过早消失，已改为仅新事件续期。补充QA在2.6秒再次发同文新事件，验证越过原3.2秒期限仍显示并最终消失。该测试于r11通过16.766秒；完整运行manifest待持续滑动用例结束后写入。

整体滑动性能不因这些UI测试通过而记为通过。未推送、未发布、未覆盖手机。


独立全迁移审核发现两类调用端边界：用户再次主动触发同文失败没有新event（屏蔽标签、标签超限、保存条件），以及诊断重试开始时旧error跟新revision提前弹出。已安排仅调用端修复，保持后台持续错误去重；最终状态待针对性真实入口回归及再审核。
