# 全页面悬浮栏修复 173

## 问题与实现

普通页面曾把系统安全区及栏高作为容器外部占位；列表只绘制中间区域，导致顶端、底端白带。转场又沿用阅读区域裁图，无法接管整屏像素。普通顶栏外框、内层按钮与轨道重复叠底色，视觉上接近不透明。

173 将内容画布、滚动让位、固定控件、手势阅读区域分开。根宿主与业务整页宿主传递真实安全区，内容画布覆盖全屏；初始/末尾让位改为 scrollContent margins。固定栏位置保持不变，普通栏共用 0.86 透明度，内层背景不重复叠白。根切页采集整屏无控件内容，固定头尾独立交接；边缘返回沿用同一顶部像素层，并将底部交接扩展至 Home 区和横屏左右边缘。目标实屏就绪后才移除接管层。

标签选择的搜索/分段控件并入三行悬浮顶栏；详情多标签操作悬浮于底栏上方，选中时增加滚动让位；兼容播放器内容扩展至整屏。覆盖范围含四个根页面、设置和管理子页、作者页、筛选/选择/编辑整页、详情以及原生/兼容播放。系统授权浏览器及系统弹窗保持系统管理。

## 兼容播放嵌套关闭

第八轮准备本地文件后，实际进入兼容播放、共享底栏、分享入口和 WebView ready 检查均通过；关闭时却连原生播放一起退出到收藏。原 Compatibility 页仅调用环境 dismiss，而源视频位于 NativeMediaPager 的独立 UIHostingController 中。修正改为显式 onClose，并由唯一调用方核对 request UUID 后清空该兼容请求，避免关闭操作跨层。独立高级审核确认这是最小改动；源码审核通过。第九轮验证关闭、原生保留、重新打开与切底栏，结果另记。

第九轮同一关闭后入口等待失败仍为 UNKNOWN，不能据此认定外层确实被清理；显式 onClose 本身没有消除该轮失败。第十轮启用既有 collection-batch-manage fixture（它同时准备有效收藏 membership 与生命周期日志），完整测试通过（29.809 s）：首次关闭只 finish 兼容 session43AC，随后创建第二次兼容 session09DDD；原生 session861087 只在最后切底栏时 finish。独立审核根据这份日志撤回环境 dismiss 根因推断，不建议扩大修改 owner cleanup。该通过与第九轮失败保留并列，不能当作重复失败已确定根因。
