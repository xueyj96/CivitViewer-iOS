# 166 正文让位与会话内状态

本轮根据用户“内容让位”的澄清，直接比较 ExHViewer 当前 FloatingFeedLayout 和 chrome-state-map 140／141／143。顶部目标沿来源留空横向到位后，同一真实 pane 随固定栏时钟让位；中段目标始终保留本页留空与视口。顶栏上沿和底栏位置固定。详细状态图与边界见 ../content-clearance-166.md。

## 实施与审核

- root 转场增加 body-live 阶段，仅交出正文快照，继续持有同一 token 的固定栏、tone 和输入 lease；真实页伸缩到目标后才清理。不纵向缩放或平移旧截图模拟让位。
- clearance plan 同时绑定 tab 与具体 bar 的 contentOwner，防止被覆盖的旧页误用目标留空。missing header、renderer 失败或高度不到位均 visual aborted；已提交的导航结果不被重写。
- 搜索保留作品／作者的两个稳定 pane、独立 store 和位置；隐藏模式停自动加载，scope 不匹配时不显示旧作品 feed。显式新提交与临时切换模式分开。
- 作者作品补 per-kind 网格锚点。MediaGrid 恢复仅由 scrollPosition 负责，移除 onAppear 的第二次 scrollTo；显式 caller scrollRequest 保留。
- 常规 title 页读取自身滚动状态；标签选择、历史、下载由选中 pane 发布；作者选择复用已存在的精确发布者。媒体页不探测 scroll。iOS17 无实际位置记录时按保 viewport 处理；iOS18+ 用实际几何阈值。17 fallback 本轮为静态／编译核验，没有宣称在17设备运行过。

独立高级审核发现并修复 owner 作用域、replace 失败收尾、Search 旧 scope 预览以及 iOS17 unknown 误报顶部四类问题。最终只读审核无剩余静态阻断。评审及抽帧均限定本轮变更与实际录制路径。

## 性能证据与限制

165同一1000作者榜→搜索基线三轮为1.94／1.74／2.00s，包含XCTest截图、层级查询和idle等待，不能当纯转场延迟。18次header raster中位3.43ms；第一次179.25ms，其余最大5.48ms。首个冷renderer仍是已记录的性能调查项，本轮没有通过预热搬移耗时或猜测性改缓存来宣称修复。

最终166同一用例再次通过，源码摘要与r4一致。三轮为1.87／1.80／1.76s；18次raster中位4.03ms，第一次50.53ms。少量样本和系统字体／绘制缓存会影响冷耗时，两轮不足以证明代码带来确定的帧率或冷渲染改善。比较原始值见build/performance166-comparison.json。

一次仅附加受控模拟器App的Time Profiler有效录制6.54s；目标测试退出后即停止，14MB。该窗口1.32s采样权重中，约444ms在XCTest accessibility snapshot分支。Hangs记录门槛250ms，该窗口无条目；它没有覆盖首次冷renderer，也没有Animation Hitches lane，不能据此称用户报告的卡顿已全部消失。本轮确定修复的是模式切换重载和返回二次定位等状态／布局断层；用户具体感到拖动、等待还是滚动卡顿的问题仍待对应动作确认。
